## Architecture

```
ADMIN (progressive)     BROWSE (on-demand)      LAT QUEUE (eager)
Full dataset backfill   Fetch-per-query         Small fixed dataset
Client-side filtering   Live query → loadSubset WHERE is_making=true
~48MB (no heavy JSONB)  Minimal columns          Admin columns
```

## Key Changes

**`frontend/src/lib/db/index.client.ts`** — Complete rewrite
- Column sets: `UK_LRT_ADMIN_COLUMNS` (excludes 7 heavy JSONB), `UK_LRT_BROWSE_COLUMNS` (minimal)
- Singleton factories: `getAdminCollection()`, `getBrowseCollection()`, `getLatQueueCollection()`
- Shared `shapeErrorHandler()` + `monitorSyncStatus()`
- Removed: `pageCollections`, `needsShapeExpansion`, `buildWhereFromFilters`, shape expansion code

**`frontend/src/lib/db/query-helpers.ts`** — NEW
- `filtersToWhereCallback()` maps FilterCondition[] to TanStack DB query predicates
- Operators: equals, contains, greater_than, is_empty, in, etc.

**`frontend/src/routes/admin/lrt/+page.svelte`**
- Uses `getAdminCollection()` (progressive sync, no WHERE)
- All filtering via TableKit's built-in `applyFilters` — no handleTableStateChange
- No hidden year scope — full dataset available after backfill

**`frontend/src/routes/browse/+page.svelte`**
- Uses `getBrowseCollection()` (on-demand) + `createLiveQueryCollection`
- View changes rebuild live query → triggers loadSubset → fetchSnapshot
- Previously fetched data stays cached in collection

**`frontend/src/routes/admin/lat/queue/+page.svelte`**
- Uses `getLatQueueCollection()` (eager, `is_making = true`)

## Notes
- Root cause: every filter change called `updateUkLrtWhere()` → full shape re-sync
- First approach (smart shape expansion) rejected — still fights library design
- Progressive mode: first query loads via fetchSnapshot, full dataset backfills in background
- On-demand mode: starts at offset=now, each live query triggers targeted fetch
- Excluding 7 heavy JSONB columns saves ~50% payload for admin sync
