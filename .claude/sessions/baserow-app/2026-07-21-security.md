# Baserow App Security

**Started**: 2026-07-21
**Meta**: `baserow-app/2026-07-18-meta.md`

## Research Findings

### User Sources
- A User Source maps a Baserow table (Email, Password, Name, Role) to app auth
- Three auth methods: Email/Password (all plans), SAML 2.0, OIDC (Advanced+)
- Deleting a user row = revoking access
- Multiple user sources per app supported
- All API-configurable: `/api/application/{id}/user-sources/`

### Auth Flow
- Login Form element (email/password) on a page with visibility "All Visitors"
- All other pages set to "Logged-in Visitors"
- Unauthenticated users auto-redirect to login page
- Baserow issues its own JWTs (UserSourceToken)

### RBAC
- Element-level, not page-level (pages are only public-or-authenticated)
- Role = single_select field on Users table
- Elements: show/hide by role (Allow/Disallow specific roles)
- Server-side enforcement, not CSS-only

### sertantai-auth Integration
- Cannot pass external JWTs directly to Baserow
- OIDC route: sertantai-auth as OIDC provider → Baserow user source (Advanced plan)
- Table sync route: mirror users from sertantai-auth into Baserow users table (any plan)
