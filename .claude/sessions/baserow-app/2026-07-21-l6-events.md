## Scope

Two customer-entered data tables need App Builder pages:
1. **Compliance Events** — the L6 canonical entity (22 fields, full lifecycle)
2. **Incidents** — safety/enforcement incidents (13 fields)

Both use the same-page create+edit pattern. Both link heavily to existing layers.

## Notes
- Events are source-agnostic: fractalaw, sertantai-enforcement, customer manual entry all produce same schema
- Events are the provenance anchor — every downstream compliance change traces back to the triggering event
- Compliance Events filter: `Legal_Register link_row_contains page_parameter.law` (same pattern as Duties/Controls)
- Lifecycle: Detected → Triaged → Assessing Impact → Responding → Closed
