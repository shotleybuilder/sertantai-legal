## Research Findings

### Baserow Application Builder
- 30+ visual elements: forms, tables, buttons, inputs, repeaters, columns, menus
- **CRUD capable**: Form element creates/updates rows, Table element displays with inline edit
- Data sources connect pages to tables with filtering (List Rows, Get Row, Summarize)
- Actions on events (button click → update row, navigate, show notification, send email, etc.)
- Multi-page apps with login, shared headers/footers
- Custom Code element for JS/CSS
- Can be published as standalone web apps
- **API-driven**: everything UI-doable is API-creatable — Apps are part of the onboarding pipeline

### Baserow Dashboards
- 5 widget types: Summary, Bar Chart, Line Chart, Pie Chart, Doughnut
- Aggregations: count, sum, average
- Multi-table: widgets from different tables on one dashboard
- Auto-refresh when data changes
- Good for KPIs / overview, NOT for workflow
- Deferred until assessment data exists to dashboard

API patterns discovered:
- Data sources need `local_baserow` integration or show "Incomplete configuration"
- Element PATCH: `/api/builder/element/{id}/` (not page-scoped)
- Link_row formulas: `get("current_record.field_XXXX.*.value")` for display text
- Single_select formulas: `get("current_record.field_XXXX.value")`
- Table link fields: no `value` property, use `navigate_to_page_id` + `page_parameters`
- Publish: create domain (`POST /api/builder/{id}/domains/` with `xxx.baserow.site`), then `POST /api/builder/domains/{domain_id}/publish/async/`

SaaS API limitations (require UI):
- `parent_element_id` — can't nest elements in containers via API
- Workflow action service PATCH → 500 — can't configure Update Row field mappings
- Table link field value — link text must be set in UI
- Full details: `baserow-app/2026-07-18-phase-1-continuation.md` § API Patterns
