# Session: Issue #175 Local CLML store (CLOSED)

## Problem

Every parse, diff and repair re-fetches CLML from legislation.gov.uk; `Client.fetch_xml/1` keeps nothing. The LAT parser coverage work fetched the same fragments twice (dry run, apply) and has more corpus-wide passes queued (#174 sibling lists/BlockText, P1group titles, ConfersPower, the remaining list-text repair batches). Requests are rate-limited (~1 s), and legislation.gov.uk returns intermittent 502/504s. Brought forward by Jason (2026-10-07): store first, then the remaining passes run against it.

## Design (2026-10-07)

- **What is stored**: legislation documents fetched as XML through `Client.fetch_xml` — paths `/<type>/<year>/<number>/…/data.xml` (body, fragments, introduction, contents). Not changes feeds, `/new/` lists or search (they change by design). A 404 is stored as a marker too, so the `regulation → article → rule` fallback isn't retried.
- **Layout**: `data/cache/clml/<path>.gz` + `<path>.meta.json` (`fetched_at`, `dct_valid`, `status`); root configurable (off in tests unless a test sets it).
- **Modes** (`fetch_xml(path, store: …)`): `:write` (default — fetch live, store what comes back; the store fills from every normal use), `:prefer` (bulk tools — use the stored copy when fresh, else fetch and store), `:only` (offline — never touch the network; a miss is an error).
- **Freshness**: a stored copy is fresh when its `dct:valid` ≥ the law's `legal_register.md_dct_valid_date` (the LRT scrape keeps that current); with no date on the law, when fetched within 30 days. `--refresh` forces live.
- **Callers on `:prefer`**: `lat.text_diff`, `lat.repair_text`, the bootstrap, and `LatStagedParser` when asked (`store: :prefer`); the admin re-parse and LRT scrape stay live (and write through).
