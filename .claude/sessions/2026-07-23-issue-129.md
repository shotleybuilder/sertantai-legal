# Issue #129: Function column stale after fractalaw updates is_making

**Started**: 2026-07-23
**Issue**: https://github.com/shotleybuilder/sertantai-legal/issues/129

## Diagnosis

Root cause: triage_subscriber sets is_making without updating function JSONB.
But the real problem is deeper — Making/Empowering/Housekeeping don't belong in
function at all. They describe obligation content (taxa domain), not structural
intra-law relationships. The composite "X Maker" tags are never consumed.

## Simplification: function = structural role only

Strip the function column down to 4 structural labels:
- **Amending** — has amending[] targets
- **Revoking** — has rescinding[] targets  
- **Commencing** — is_commencing flag
- **Enacting** — has enacting[] children

Removed from function (all derivable):
- Making → `is_making` boolean column
- Empowering → `is_making=false` + `duty_type` has values
- Housekeeping → `is_making=false` + `duty_type` absent
- Amending Maker, Revoking Maker, Enacting Maker → join on relationship arrays + is_making

## Changes

- `function_calculator.ex` — removed add_making, lookup_is_making_of_laws, classify_targets, all Maker suffix logic. ~550 LOC → ~300 LOC. No more DB lookups needed.
- `taxa_subscriber.ex` — removed merge_enrichment_function, derive_enrichment_result, enrichment labels. Now only sets is_making from duty_type.
- `triage_subscriber.ex` — removed function update. Only sets is_making + classification fields.
- `persister.ex` — simplified immediate/relationship function, updated comments.
- `law_parser.ex` — updated comment.
