# Session: Issue #165 PDF → LAT Parser (ACTIVE)

## Problem

Some in-force laws have no XML body on legislation.gov.uk, only metadata and a PDF. Without a body, they can't get LAT, fractalaw enrichment, a Making verdict or a tree. QQ-01 found two in QQ's register: `UK_uksi_1979_791` (Forestry (Felling of Trees) Regs 1979) and `UK_uksro_1947_805` (Compressed Acetylene Order 1947).

**Both PDFs are scanned page images with no text layer.**
- `pdftotext` returns 18 and 2 bytes.
- The pages are 150 ppi JPEGs; the 1947 Order's producer is "Acrobat Image Conversion Plug-in".

So this is an **OCR** problem, not just PDF text parsing. `SecondarySource.PdfParser` reads a PDF's text layer (with font metadata). A scan has no text layer, so OCR is the one missing step in front of the existing classify → persist chain.
