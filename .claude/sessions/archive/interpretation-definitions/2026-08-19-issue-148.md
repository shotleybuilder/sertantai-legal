# Session: Issue #148: Definition List Item Bleed (CLOSED)

## Problem

155 definitions have items bleeding into each other — when a definition list contains lettered sub-items (`;b)`, `;c)`), the parser doesn't split them. Sub-items bleed into the preceding definition's text, producing oversized definitions with embedded entries.

## Todo

- ✅ Investigate XML structure of affected definition lists
- ✅ Add sub-item splitting logic to definition_list_strategy
- ✅ Data cleanup of existing concatenated terms
- ✅ Run tests and diagnostic

## Dependencies

- ✅ Definition Bug Fixes Batch 5 (2026-08-19)

## Investigation

The bleed mechanism: when a `<ListItem>` in a `<UnorderedList Class="Definition">` contains a NESTED `<UnorderedList Class="Definition">`, the `.//Text` XPath recursively picks up ALL descendant text including the nested list items' text. The nested lists are already processed independently by the outer `.//UnorderedList[@Class='Definition']` search, but their text was being duplicated into the parent ListItem's definition.

Similarly, `.//Term` picked up Term elements from nested Definition lists, causing mis-attribution.

Actual affected count was 527 definitions across 104+ laws (much larger than the original 155 estimate). The Highways Act 1980 alone had 73 affected definitions, with "act of 1965" ballooning from a correct 32-char definition to 13,521 chars.

## Fix

Added `direct_text_elements/1` and `direct_elements/3` helpers in `definition_list_strategy.ex` that exclude elements from nested `UnorderedList[@Class='Definition']` subtrees before text/term extraction. This preserves legitimate sub-items in `OrderedList` elements (like the "workplace" definition's enumerated items) while excluding text from nested Definition lists that are processed independently.

## Data Cleanup

Three-phase cleanup:
1. **Primary truncation** (421 defs): regex-based truncation at `;\u201c[TERM]\u201d (means|includes|has)` bleed boundaries, including `;\u201c` and `;[letter]\u201c` variants
2. **Trailing artifact removal** (105 defs): stripped orphaned `;[letter]` suffixes (Pnumber remnants)
3. **Manual fix** (1 def): UK_nisr_2016_244 "act" — ASCII-quoted embedded term required direct update
