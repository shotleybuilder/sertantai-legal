# Migrate to PGLite as a Local Store

**Started**: 2026-03-08
**Issue**: https://github.com/shotleybuilder/sertantai-legal/issues/38
**Status**: Complete

## Problem
- In-memory storage (TanStack DB) for ~19K uk_lrt records causes frequent browser crashes
- 3 separate Electric shape subscriptions (admin progressive, browse on-demand, LAT queue eager) each with their own in-memory copy
- ~48MB JS heap usage, laptop memory pressure, unusable app

## Solution
Replaced TanStack DB with PGLite (WASM Postgres backed by IndexedDB):
- 3 in-memory collections -> 1 PGLite table in IndexedDB
- Data persists across page reloads (no re-downloading 48MB)
- `shapeKey` enables resumable sync (delta-only on warm start)
- Initial sync: 19K rows in ~5.8s via `json_to_recordset`
- Warm start: instant (data already in IndexedDB, delta sync in background)

## Architecture
```
BEFORE:  Electric -> 3 TanStack DB Collections (in-memory Maps, ~48MB+ JS heap) -> .toArray -> UI
AFTER:   Electric -> 1 PGLite table (IndexedDB, WASM Postgres) -> SQL queries -> Svelte stores -> UI
```

## Issues Encountered & Fixed
1. **Stale subscription state**: PGLite sync thought it was up-to-date because pglite-sync persisted its LSN offset, but the IndexedDB table was empty. Fix: detect empty table + clear stale subscription before sync.
2. **BigInt serialization**: Electric parses int8 (BIGINT) columns as JS BigInt, which can't be JSON-serialized. Fix: `mapColumns` callback converts BigInt -> Number; changed `md_total_paras` from BIGINT to INTEGER in schema.
3. **CASCADE drop**: pglite-sync metadata tables depend on uk_lrt; `DROP TABLE IF EXISTS uk_lrt CASCADE` needed.
4. **Schema versioning**: Added `_pglite_meta` table to track schema version; bumping version forces drop + recreate.
5. **Browser crash on admin LRT**: `SELECT *` with 19K rows + `live.incrementalQuery` (diff cache doubles memory) + `pagination: false` = crash. Fix: reduced to 12 columns via `createQueryStore` (one-shot, no live diff cache) + enabled pagination.
6. **Warm start sync status**: `onInitialSync` only fires on cold start. Fix: set `syncing: false` + `lastSyncTime` immediately on warm start when data already exists.
