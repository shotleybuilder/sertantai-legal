lessons:
  - title: legislation.gov.uk uses /note (singular) for SIs and /notes (plural) for Acts
    detail: >
      No documentation for this difference. SIs return 404 on /notes, Acts return 404 on
      /note. The fetch_first pattern tries both paths. EU retained law and pre-1999 Acts
      return 404 on both (no explanatory notes exist).
    tag: data
  - title: Floki lowercases all XML element names
    detail: >
      The legislation XML uses <ExplanatoryNotes>, <P1>, <NumberedPara> etc. Floki
      normalizes to lowercase: explanatorynotes, p1, numberedpara. CSS selectors must
      use lowercase. This applies to all Floki XML parsing, not just this feature.
    tag: tooling
  - title: SI XML uses P1/P2/P3 elements, not P, for numbered paragraphs
    detail: >
      The initial implementation used Floki.text on the whole node, producing one big
      block without line breaks. Walking P1/P2/P3 elements individually preserves
      paragraph structure. Acts use NumberedPara instead.
    tag: data
  - title: Ash codegen migrations conflict with manual migrations for view-backed columns
    detail: >
      When adding a column to legal_register manually (with view + trigger rebuild),
      mix ash_postgres.generate_migrations still creates a codegen migration for the
      snapshot sync. Make it a no-op with a comment — the column already exists from
      the manual migration.
    tag: schema
