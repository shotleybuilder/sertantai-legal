# Session: Issue #186: Position-named rows lose enrichment (CLOSED)

## Problem

Signature, table and note rows are named by their position in the law (`signed.114`). A re-parse that inserts rows before them renames them, and the enrichment carry (text matching) fails where the text isn't distinctive. CV-S02a's item rows renumbered 46 such rows; `UK_eur_2006_561` `signed.114` → `signed.157` ("...") stopped the enrichment gate and was forced with Jason's agreement (2026-10-23).

## Options for a stable name

Measured 2026-10-23 (read-only, DB + stored CLML):

| Kind | Rows | Laws | Enriched | XML id of its own | Enclosing provision id |
|---|---|---|---|---|---|
| signed (`SignedSection`) | 723 | 723 (one each) | 5 | none (IdURI `…/signature` only) | n/a |
| table (`Tabular`) | 208 | 85 | 0 | 0 of 233 | 233 of 233; 10 share a provision with another table |
| note (`Figure`, empty text) | 19 | 4 | 0 | none | all |

Live tables naming them: lat_labels_today, lat_label_timeline, lat_changes, lat_change_log(_rows); lat_section_id_renames already holds 208 past renames of these rows.

Options:
1. **By kind alone** (signed): `signed` — one per law; never moves.
2. **Anchored to the enclosing provision + ordinal within it**: `reg.7(1).table.1`, `reg.8.figure.2`. Moves only if a table is inserted before it in the same provision. Readable, ties to a named row.
3. **Ordinal within kind in the law**: `table.1…N`. Moves if any table is inserted earlier in the law.
4. **Content hash**: `table.<hash>`. Survives moves, but changes on any amendment to the table; figures have no text; unreadable.
5. legislation.gov.uk's own id: not available (no ids on Tabular/Figure; signature has only a law-level URI).

**Decision (Jason 2026-10-23):** option 1 for signatures (`signed`), option 2 for tables and figures (`reg.7(1).table.1`, `reg.8.figure.1`); Figure rows are named `figure`, not `note`.

Rows already carry their provision (hierarchy_path `part.1/provision.11/sub.1`), so the stored rows can be renamed in place — a targeted repair, no re-parse.

Open: section_type `note` → `figure` also needs compliance's LegalArticle enum (`one_of`, no `:figure`) to take the value — a compliance change.

Agreed (Jason 2026-10-23): the six checks above plus "the rename leaves sort_key unchanged; a re-parse keeps document order". Figures (a): name `figure`, section_type stays `note`.
